# dev32-E2 安装继续修复

截图中的2.5GB文本模型已经下载、SHA校验并写入成功。之后的fetch failed对应安装器下一步联网获取uv环境工具；旧版没有打印具体阶段。本修复内置同版本官方uv工具并保留校验，避免这一阶段再次联网获取工具。Python、PyTorch和声音权重后续仍需联网，不保证所有网络问题同时消失。

## 操作

1. 在“请按任意键继续”处按键关闭失败窗口。这只关闭安装窗口，不会删除已完成的下载。
2. 将本修复包解压到现有完整软件目录（能看到runtime文件夹和启动本机版.cmd的那一层），同名文件覆盖。
3. 双击“修复并继续安装.cmd”。首先校验内置uv并放入E盘工具目录，然后从安装阶段继续。
4. 不要删除E:\Stillhere-Models。若本机模型列表已有该文本模型，脚本会显示“文本模型已在E盘，复用已完成的下载”。

| 编号 | 操作与预期 |
|---|---|
| H01 | 显示Python工具已校验准备，路径为E:\Stillhere-Models\setup-tools\uv.exe |
| H02 | 显示dev32-E2和[1/6]阶段；已完成文本模型复用，不重新下载2.5GB |
| H03 | [2/6]工具准备通过；接着到[3/6]Python、[4/6]PyTorch/依赖、[5/6]CUDA、[6/6]声音模型 |
| H04 | 若失败，窗口给出“安装停在：具体阶段”和可用的网络错误代码；发该段截图，不必重装全部软件 |
| H05 | 全部完成后，按原dev.32目录验证记忆、语气和真实声音；本修复不代表真实模型生成已验证 |

内置uv来自官方0.13.7发布，保留MIT/Apache许可证。ZIP及uv.exe均按既有固定SHA校验，没有关闭TLS、下载地址安全检查或变更DNS/代理。

开发验证：校验后复制、损坏文件拒绝覆盖、E盘路径、独立服务和启动器回归测试通过。Windows实际Python/CUDA安装及声音相似度仍需验收。
