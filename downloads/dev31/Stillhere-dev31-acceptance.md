# dev.31：声音转写准确性专项验收

交付日期：2026-11-06。本轮只验转写改进。改用中文通用/川渝方言两个Paraformer模型；不再使用dev.30的Whisper tiny。完整包内置两套权重，体积显著增加，不需要另填密钥或上传云端。

## 升级

停止旧服务，完整解压新版，启动新版目录的启动本机版.cmd，使用新地址与原凭证登录。原素材库保留。必须看到“中文专用双模型”和“说话类型”选择框；只刷新旧目录的网页不会升级模型。

## 依次验收

| 编号 | 操作 | 预期与记录 |
|---|---|---|
| D01 | 用原来识别不准、尚未确认入库的同一素材进入“整理 / 校对入库” | 原素材仍在；显示两种说话类型，不需要重录或调整原音频。已确认入库的稿继续受覆盖保护，请先保留正式记忆，不用删除它来测试 |
| D02 | 保留dev.30识别文字截图或下载稿；选择“普通话 / 带四川口音的普通话”，同意后识别 | 新结果与实际声音逐句比对，记录漏句、错词、人名、地点、时间和数字；不要先人工改字再计算效果 |
| D03 | 对同一条未入库素材选“四川话 / 重庆话（方言）”，重新勾选转写同意；允许替换测试稿 | 重新识别；“最近一次其他转写结果”中保留上次机器识别原文，可以对比。更换模型不自动修改记忆库 |
| D04 | 选择最贴近实际语音的结果 | 分别记录两种模型哪一种更好。如果普通话用方言模型反而更差，这是需要记录的真实结果，不要求每条都由方言模型胜出 |
| D05 | 检查15—60秒、句子中间有自然停顿的测试素材 | 前后内容都有，无明显因切段造成的半句话；按停顿优先分段，每段最多20秒，无明显停顿时仍有长度兜底，不承诺消除所有边界错误 |
| D06 | 检查低音量或声音爆音的普通测试素材（有条件再做） | 转写完成时，检测到低音量/削波会提示重新检查收音。轻度音量补偿只用于识别临时声音，不修改原件；收音提示不代表准确率置信分 |
| D07 | 刷新并重新登录，打开测试稿 | 最新识别稿、模型来源和最近识别对比仍保留；未明确确认前不进入记忆库 |
| D08 | 纠正少量错字并保存，再选择片段和范围明确确认入库 | 人名/数字等以本人校对为准；原音视频不变，确认后才用于回答 |

建议D02、D03至少比较三段：普通话自我介绍、自然讲故事、四川话/重庆话表达。先用相同素材比较模型，避免同时改变手机位置、美颜/音频处理或麦克风，导致无法判断改善来自哪里。

## 如何判定准确性

不以“文字更通顺”为标准，要和原始声音一致。单独记录：

- 关键事实有没有变：姓名、年龄、时间、地名、亲属关系、金额。
- 是否整句漏掉、多出原话没有的句子，或无声时出现文字。
- 两种模式与旧版比较：更好/相当/更差；列出2—3处原话与识别文字。

公开6段川渝语音样本（总计177个归一化参考字符）对照结果：tiny CER 84.75%、中文通用10.73%、川渝专用7.91%。这些是上游选取的短样本，可能有选样/分布偏差，不代表客户录音或普通话总体准确率。算法没有调用大模型润色，原始词句仍需本人核对。详细方法与来源见包内docs/ASR准确性对比_dev31.md。

## 边界

- 四川口音的普通话优先试中文通用；实际川渝方言再试方言专用。不能因为客户在四川就强制用方言模式。
- 低音量、噪声、多人抢话、音乐、人名和专有词仍可能出错。当前未接专有人名热词模型、独立标点模型或自动纠错，不会擅自把听错内容改成“合理故事”。
- 本轮未测试客户当前电脑的性能、实际录音或方言准确率；Windows二进制未在Linux环境执行。开发测试用真实模型完成音视频转写、模式切换、历史保存、取消与版本冲突保护；149项Node测试通过。
- 已确认入库的素材禁止直接重转写覆盖，防止已确认事实被机器结果替换。测试稿未入库前可比较两种模式；如果原素材已确认入库，请反馈，不要删除正式资料。

反馈格式：D01通过；D02中文通用比旧版更好/相当/更差；D03川渝模式更好/相当/更差；原话“……”被识别为“……”。如仍有明显错误，需要原始声音及本人确认的对应文字才能进一步定位，截图不能替代音频。
