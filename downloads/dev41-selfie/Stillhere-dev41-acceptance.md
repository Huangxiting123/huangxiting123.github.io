# 续在 dev41 · 根据微信对话生成本人模拟自拍

## 升级与准备

关闭旧续在客户端，安装 dev41 到原客户端目录（建议 E 盘）。E:\Stillhere-Models 和 %LOCALAPPDATA%\Stillhere-Local 继续保留，无需重新下载现有模型。已加密保存的 ArtFlow Key 会沿用。

你已在 dev40 验证普通图片生成成功，但参考照片使用 `/v1/images/edits` multipart 接口，需要单独验证。若平台不接受该接口，会显示 HTTP 状态；不会降级为陌生人的图片。

## 按顺序验收

1. SF01：设置与工具中确认 ArtFlow Key 和完整图片模型名称仍在。生成杯子的成功只说明文生图正常。
2. SF02：进入「我的自拍」，选择一张本人清晰单人照片。程序将图片规范化、缩小到最长768像素并去除原文件元数据。请勿使用未授权的他人照片。
3. SF03：仔细阅读并勾选云端处理授权：参考照片、最近微信对话片段、相关已保存场景会发送给 ArtFlow，可能按平台收费。选择每日尝试上限（默认5次，最多30次），勾选启用微信自拍，再保存。
4. SF04：点击「用参考照片生成测试自拍」。这是一次真实的云端请求，可能计费。查看人物是否像本人、图中是否带 AI GENERATED 标记。首次参考人像测试成功后再进行微信测试。
5. SF05：保存常去场景：培养我的分身 → 完整培养工具 → 场景，例如“家中客厅，靠窗有茶桌”。不用填写真实住址。
6. SF06：微信连接 → 扫码授权 → 开启自动回复。先正常聊两三句，例如“今天想在客厅喝茶”，再发送“给我发张喝茶的自拍”或 `/自拍`。
7. SF07：手机先收到 AI 模拟说明，再收到原生图片消息。检查是否保持参考人像、画面是否结合最近对话。它不是实时实拍，不能作为本人真实行踪的证明。
8. SF08：继续聊天换话题，例如“现在想去公园散步”，再明确要求一张散步自拍。程序参考最近8条微信消息，以及最多8个已保存场景；普通“在干嘛”不会自动触发计费图片。
9. SF09：一分钟内重复请求应被拦截，超过每日上限应被拦截。每一次已提交的生成尝试都计数，失败或超时可能也已被上游计费；不会自动重试。
10. SF10：生成中在「我的自拍」立即停用，或暂停微信自动回复。尚未发送的照片不得继续发送。已经上传给平台或已被微信接受的内容不能靠停用撤回。
11. SF11：删除参考照片与授权后再请求自拍，应提示重新配置；原有记忆、声样和正常微信文字/语音继续可用。
12. SF12：重启客户端，照片和启用状态保留，微信需要重新扫码。每日尝试次数不会因重启或删除再添加参考照片而清空。

## 当前边界

- 根据文字上下文模拟拍摄，不会访问摄像头、定位或真实拍照。图片角度、身份相似度与场景还原由实际模型决定，需要试听/看图验收，不能保证每次一致。
- 明确索要自拍/照片时才生成。没有开启主动定时发送，也不自动生成视频。
- 不把全部记忆库、资料档案或 API Key 作为图片提示词上传。仅使用本人参考图片、最近微信对话（最多8条，每条截断）和已保存的场景文字。
- 微信文字、图片分开提交。若图片发送结果不确定，不自动重发。看到“接口已接受”不等于已证明手机成功收到。
- 当前参考生成需要兼容 `/v1/images/edits` 并返回 Base64 图片。平台仅返回 URL 或不支持图生图时，需进一步适配，不会静默改为无参考图生成。
- 微信仅支持扫码者自己的 ClawBot 会话，不接管普通好友或群聊。

## 工程验证范围

自动化覆盖：参考授权、上下文选择、multipart 参考图片请求、限额持久化、暂停/撤销拦截、官方微信图片消息/AES上传格式、普通聊天不触发图片、Windows 原生图片规范化与 AI 字样叠加、客户端启动及原有回归。没有使用用户真实 Key、参考照片或微信账户进行远端实测。最终参考人像效果和手机送达以 SF04、SF07 为准。

微信协议依据：[腾讯官方类型](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/types.ts)、[图片上传实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/cdn/upload.ts)、[原生图片消息](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts)。
